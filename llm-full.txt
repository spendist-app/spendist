# Spendist: full LLM reference

## Identity and scope

Spendist is a GPL-3.0 open-source personal-finance application for recording and understanding personal money. It stores financial records and produces summaries. It does not initiate bank payments, give tax/accounting/investment advice, or make financial decisions for the user.

The hosted application is `https://spendist.app`. The source is an Nx workspace and the UI supports English and Polish.

## Shipped user-facing capabilities

- **Authentication and account security:** email/password sign-up and sign-in, password-recovery email, reset-link session handling, authenticated password changes, and permanent self-service account deletion. Deletion requires the current password plus explicit confirmation, removes avatar objects, and cascades user-owned database data from the deleted Auth user. New users receive default categories.
- **Transactions:** create income/expense records with date, description, amount, currency, wallet, category, optional tags, and optional place. Users can edit, duplicate, delete, filter, sort, search, and create transactions in bulk from pasted rows. Default-currency conversion uses stored exchange rates where applicable.
- **Financial organization:** profile/avatar, wallets with currencies/default status, category groups, nested categories, colors, Heroicons, and reusable tags.
- **Recurring payments:** scheduled income/expense with fixed or variable amount, category, wallet, currency, tags, schedule, and optional end date. Scheduled Supabase work creates automatic transaction records; it never makes a real payment.
- **Places:** reusable locations/merchants with optional address and note metadata. Users can attach them to transactions and inspect annual spending totals.
- **Dashboard:** up to 12 calendar months of cash flow, selected-month category/tag totals, recurring-created transaction totals, and yearly place spending, scoped by wallet where relevant.
- **Notifications:** user-scoped Realtime notifications for recurring activity and exchange-rate-sync failure; users can mark all visible unread items as read.
- **Data portability:** Kontomierz XLSX import to a chosen wallet; readable, filtered Spendist CSV export; CSV analysis before import, valid reference-data creation, and duplicate skipping. Spendist CSV and Kontomierz flows are separate.
- **Preferences:** persisted English/Polish choice and light/dark theme. Signed-out navigation uses accessible flag buttons in a compact single-row header; changing language on a blog URL opens the other edition's home page.
- **Public blog:** separate Polish and English Markdown collections for signed-out readers. Each edition can publish unrelated articles, categories are indexable when non-empty, tags are filter-only and `noindex`, and sharing uses Web Share/copy/plain social links without embedded social SDKs. There are no comments, CMS, or admin panel.

Read `doc/features/` for feature-level details and deliberate limits.

## Routes and visibility

| Route | Purpose | Indexing |
| --- | --- | --- |
| `/` | Public landing page; authenticated users redirect to product home. | Indexable |
| `/pl/blog`, `/en/blog` | Independent Polish and English blog indexes. | Indexable, including the initial empty state |
| `/{locale}/blog/{slug}` | Published locale-specific Markdown article. | Indexable and prerendered |
| `/{locale}/blog/category/{categorySlug}` | Non-empty localized category archive. | Indexable and prerendered |
| `/{locale}/blog/page/{page}` | Blog pagination, 12 posts per page. | Indexable and prerendered |
| `/{locale}/blog?tag={tag}` | Client-visible tag filter. | `noindex,follow`; excluded from sitemap |
| `/{locale}/blog/feed.xml` | Locale-specific RSS 2.0 feed. | Discovery file, not an HTML page |
| `/login`, `/signup` | Authentication entry points. | Not indexed |
| `/forgot-password`, `/reset-password` | Password recovery utilities. | Not indexed |
| `/dashboard`, `/home`, `/transactions`, `/settings` | Authenticated product pages. | Not indexed |
| `/modules/recurring-payments`, `/modules/places` | Authenticated modules. | Not indexed |

Routes live in `apps/web/src/app/app.routes.ts`. Public SEO files live in `apps/web/public/`. `sitemap.xml` has canonical indexable content only; `robots.txt` disallows private/utility routes.

## Blog publishing and SEO pipeline

- Source content is in `apps/web/content/blog/pl/` and `apps/web/content/blog/en/`; the collections and category catalogs are independent and individual articles have no `hreflang` pairing.
- Article front matter, image requirements, and the publishing checklist are documented in `apps/web/content/blog/README.md` and `doc/features/public-blog.md`. The repo-local `add-spendist-blog-post` skill turns supplied Markdown into the real localized `{slug}.md` file and always leaves it as a draft.
- Original article raster files are isolated in `apps/web/image-sources/blog/{locale}/{slug}/`. Body Markdown references logical `image:asset-name` IDs; it never links directly to generated filenames.
- `npm run images:generate` creates width-based AVIF/WebP candidates up to 1600 pixels, an opaque JPEG or transparent PNG fallback, `media-manifest.json`, and an Angular manifest. Other public pages use the same pipeline under `apps/web/image-sources/site/{feature}/` and render through `ResponsiveImage`.
- `npm run blog:generate` validates front matter and logical cover/body images, renders sanitized responsive Markdown, calculates headings/reading time, and writes `blog-content.generated.ts`, both RSS feeds, `sitemap.xml`, and `robots.txt`.
- The Nx build depends on `responsive-images-check` and `blog-content-check`, so stale generated artifacts fail the build. Commit source and generated files together.
- Blog pages set canonical, robots, Open Graph, Twitter card, RSS discovery, and JSON-LD metadata. Blog homes use reciprocal PL/EN alternates; articles do not because they are editorially independent.
- Public blog routes are statically prerendered. The Cloudflare Worker returns the localized branded blog fallback with HTTP 404 for unknown blog URLs.

## Architecture

- `apps/web/src/app/app.config.ts` enables hydration, zoneless change detection, routing, Supabase, Transloco, and the production service worker.
- Standalone page components and page-local signal stores are colocated. Cross-cutting services, guards, Supabase setup, notifications, language, and theme are in `core/`.
- `en.translation.ts` and `pl.translation.ts` are the translation sources. Every user-facing key needs both languages.
- `apps/web/worker.ts` serves Cloudflare assets, exposes runtime `/env.js`, handles HTML fallback, and adds security headers. Do not judge production behavior from the development server alone.
- Supabase provides Auth, Postgres, RLS, Storage, Realtime, Edge Functions, `pg_cron`, `pg_net`, and Vault. Migrations are under `supabase/migrations/`; generated types are in `libs/data-access/supabase-types/`.
- `supabase/functions/delete-account/` owns permanent account deletion. It derives identity from the bearer token, reauthenticates with the submitted current password, removes the user's avatar folder, and uses the service role only inside the function to delete the Auth user.

## Operational constraints

- Preserve data ownership and portability. Do not add tracking, ads, data sales, or external financial access without explicit approval.
- The production database is live. Prefer additive/backwards-compatible migrations; destructive changes need an approved migration/backfill plan.
- Preserve RLS ownership checks and user-scoped notification queries.
- Use Angular signals and zoneless-safe patterns. Do not assume `NgZone` patches arbitrary callbacks.
- Validate with Nx targets and focused tests. E2E uses a dedicated local Supabase database URL, never production.

## Documentation contract

For each new or materially changed user-visible feature:

1. Update the English page in `doc/features/`.
2. Update this file and `llm.txt`.
3. Update translations and tests when implementation requires them.
4. For a public indexable route, update `apps/web/public/sitemap.xml` and `apps/web/public/robots.txt` in the same change.

Never describe planned work as implemented; label it **Planned**.
