# Consent-based public analytics

Spendist uses GA4 stream `G-WY8ZY07NGW` to measure public visits after explicit consent. The first-party banner has equal accept and reject/withdraw buttons, Polish and English copy, a privacy link and no preselected acceptance. Analytics preferences at the bottom of every page reopens it, including for signed-in users who want to withdraw a previous decision. Refusal never blocks the application.

The browser stores the decision under `spendist.analytics-consent` for 180 days. Malformed, expired or inaccessible persisted consent never grants permission. If writes are blocked, the current document can remember an explicit decision but later loads ask again. Withdrawal deletes `_ga` and `_ga_WY8ZY07NGW`; other cookies and Supabase data remain untouched. GA cookies are host-only, expire within 180 days and are not renewed for each measurement. Storage events propagate withdrawal across tabs; an expiry timer also stops measurement without navigation.

The integration waits for initial Supabase authentication to resolve. Only signed-out users on exact paths generated from the public sitemap are eligible: home, legal pages, published blog articles, indexes and valid category/pagination pages. Login, signup, password recovery/confirmation, invitations, OAuth and every authenticated route are excluded. Query strings, fragments, referrers, account IDs, financial data, emails and form contents are never passed to the runtime. The event uses a generic Spendist title and the origin plus allowlisted path. It does not provide app usage statistics or track public-page clicks/forms.

Google runs in a disposable same-origin `/analytics/frame.html` document, created only after consent. It has no application DOM or SPA history. A source/origin-checked ready handshake passes only the allowlisted path. On navigation start the host sets Google's disable flag synchronously and removes the frame, destroying its timers/listeners; a new frame may be created only after an eligible public navigation finishes. Authentication, withdrawal, expiry and cross-tab changes also remove it. Late callbacks cannot reactivate a removed frame. Removing a script element alone would leave library listeners alive, hence document isolation. The tag may produce GA session/engagement events for that isolated public visit; it never receives private route changes.

The runtime uses basic consent: no external Google tag or cookieless ping before acceptance or after rejection. It configures manual page views, denies all advertising consents and disables Google Signals and advertising personalization. No user ID is configured. The frame uses no-referrer for its own request and the external script.

Selective Worker-first routing in `wrangler.toml` ensures headers are applied to public HTML and `/analytics/*`, including Cloudflare's extensionless frame redirect; static bundles and images keep asset-first serving. The Cloudflare Worker keeps the application script CSP restricted to self. Only the utility frame can load Google Tag Manager and connect to Google Analytics; the frame can embed only under the same origin, with no forms and noindex/nofollow. The Node SSR server applies equivalent headers. Direct navigation to the utility frame does not initialize analytics. The Angular service worker excludes `/analytics/**` from navigation fallback so extensionless redirects cannot become nested copies of the application. HTTP loopback development omits HTTPS-upgrade CSP for its same-origin frame; production HTTPS retains that directive. It is absent from the sitemap. Blog generation produces the analytics path module together with the sitemap so future published content stays in sync.

Provider-account settings are outside this repository. Before production rollout the operator should disable Enhanced measurement and advertising integrations, choose minimal event/user retention (recommended two months) and review applicable Google terms. The actual account settings and retention have not been independently verified; the public policy distinguishes cookie lifetime from Google report retention. See `docs/legal/README.md`.

Implementation: `core/public-analytics.service.ts`, `core/analytics-consent.*`, `public/analytics/*`, `worker.ts`, and the generated `pages/blog/analytics-paths.generated.ts`. Unit tests cover gating, auth transitions, sanitized handshakes, withdrawal, expiry, cross-tab changes and SSR. Browser tests stub all Google requests and Supabase so validation sends no real analytics or database writes.
